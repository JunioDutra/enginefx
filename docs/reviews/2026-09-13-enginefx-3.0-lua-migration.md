# Review de implementação — EngineFX 3.0 / Etapa 1C

Registro histórico da implementação. A validação e as correções posteriores estão na [revisão conjunta dos blocos 1B/1C](2026-09-13-lua-blocks-review.md).

Data: 13/09/2026.

## Entrega

- O fixture histórico `object.json`/`move.js` foi convertido em `object.lua`. A regressão usa `LuaComponent` e uma API de jogo explicitamente autorizada; Lua nunca recebe o `GameObject`.
- `ClasspathResourceResolver` carrega módulos do classpath sob uma raiz declarada. O DinoFX usa esse resolvedor para um módulo Lua empacotado.
- O caminho JavaScript foi removido: `SceneJs`, `ScriptJsComponent`, `ScriptBuilder.createJs`, `ResourceManager.script`, `Invocable`, `ScriptEngineManager`, extensão `.js`, `nashorn-core` e o merge de serviços do JAR consumidor.
- `ScenesDefinition` recusa `type: "js"` com `SCRIPT_TYPE_REMOVED` e uma orientação para Lua.
- EngineFX foi publicada localmente como `enginefx:enginefx:3.0.0`; DinoFX consome essa versão e possui `LuaHiddenDemo`, uma cena fora do menu que valida `setup`, `update` em segundos e `dispose`.

## Validação

- `enginefx> .\mvnw.cmd -B test`: 44 testes, zero falhas/erros/ignorados no JDK 25.
- `enginefx> .\mvnw.cmd -B install`: artefato `enginefx-3.0.0.jar` instalado localmente após a mesma suíte verde.
- `dinofx> .\mvnw.cmd -B test`: 5 testes, zero falhas/erros/ignorados contra a 3.0.0.
- `dinofx> .\build.ps1 -Smoke -PresentMode fifo`: JAR shaded com LuaJava/Lua 5.4, sete cenas em duas passagens fora do checkout.
- Smoke focado na cena oculta, executado da pasta vazia gerada: duas visitas aprovadas; carregamento, callback de atualização e descarte Lua confirmados.

O smoke continua sendo uma verificação de integração Vulkan/JAR, não um aceite visual, de driver ou de Native Image. A próxima etapa é 1D: remover a criação reflexiva de cenas e tornar o bootstrap compatível com Native Image.
